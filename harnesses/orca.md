# Orca ecosystem (Continuum)

Distinguish:

1. **onorca.dev** — commercial Orca IDE / agent launcher (Prime Agent appears as a supported agent). Not the same as Continuum’s open repos.
2. **OrcaReplay** — https://github.com/Continuum-AI-Corp/OrcaReplay — record/replay/fork agent runs. Capture grows past proxy I/O (origin of each model call; multimodal / vision payloads; **agent structure** the proxy cannot see via `#65`; **LangGraph graph nodes**, including no-model nodes, via `#92`). Control flags, scrub I/O, and empty optional capture layers that cannot be honoured should fail loud, not silently no-op or under-count. Viewer timelines must grow rows when new capture layers ship (`#84` merged). Thick capture layers (MCP) need an end-to-end check — the first check found a bug (`#87`). Gateway push/pull/fork paths should announce when a run cannot reach or fork (`#85`/`#89`). Writer / command paths should produce gatewayable traces (`run.start`/`run.end` brackets — `#90`); `pull` should verify integrity before swap (`#91`). Integration docs must measure SDK env reads before asserting none — `@ai-sdk/openai` honours `OPENAI_BASE_URL` since 2.0.41 (`#99` merged / #80).
3. **OrcaCode Review** — https://github.com/Continuum-AI-Corp/Orca-Code-Review — PR review harness + merge gate via OrcaRouter. Judge / gate failures fail closed and name the gate. Reaction settle and clean-verdict publishing should share one authoritative-run planner (identity + current-head / no-newer-sibling), not per-site local guesses (`#54` open for #39).
4. **OrcaRouter-Lite** — https://github.com/Continuum-AI-Corp/OrcaRouter-Lite — self-hosted OpenAI-compatible router. Forward client fields (`parallel_tool_calls`, `max_completion_tokens`, `logit_bias`); normalize LangChain `json_schema` shapes before LiteLLM; prefer the most specific `AuthError`; surface undecryptable keys after encryption-key rotation (never re-seal with a known-dev key); advertise hosted fallback (`x-orca-fallback`); treat `top_p < 1` as non-deterministic without a `seed` (see 2026-09-21 learnings); bump prompt-cache key space when those rules change (`#155` merged). Streaming usage synthesis must match LiteLLM's real usage-frame shape or clients double-count (`#154`); dashboard `[REDACTED]` is no-change, never a key to validate or store (`#145`); allowlist write path needs thread resolution under `required_review_thread_resolution` plus an on-record TOCTOU answer (`#151`). Detail: `learnings/2026-09-25-orca-router-wire-and-placeholder.md`.

Contribution tip: prefer clear local repros that do not need paid router keys when possible; treat auth/IDOR issues carefully (responsible disclosure if needed). Design redaction + match **across the seam** for image/`data:` payloads (see `learnings/2026-09-14-orca-vision-capture-and-scrub.md`). Keep capture / fail-loud / viewer in lockstep (see `learnings/2026-09-15-orca-agent-structure-and-empty-capture.md`, `learnings/2026-09-16-orca-mcp-check-and-gateway-fork.md`, `learnings/2026-09-17-orca-gatewayable-trace-and-langgraph.md`). Gateway request fidelity and auth/cache honesty: `learnings/2026-09-21-t3-orca-router-nemoclaw-opencode.md`.
